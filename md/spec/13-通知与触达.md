# 13 · 通知与触达（⚠️ 当前是断线）

## 1. 现状：三根线都建好了，没接上

| 层 | 状态 |
|---|---|
| `notifications` 表 | ✅ 存在 |
| 类型枚举（5 类）+ DTO + 列表页 | ✅ 存在 |
| `GET /notifications`、标记已读 | ✅ 存在 |
| **创建通知的代码** | ❌ **全库零处** |
| **cron / 调度** | ❌ **全仓无 `gcron`、无 cron 目录** |
| 通知偏好开关 | ⚠️ 只写 localStorage（key `notif_prefs`），**后端无端点** |

⇒ **用户永远收不到任何通知**。同理受影响的还有：
- `tasks.reminder_at`（有字段、能写、能展示，**没人消费**）
- `recurrence_rule`（**只存不生成**）
- 习惯中断预警（设计好了，依赖通知引擎）
- 纪念日提醒（依赖通知引擎）

## 2. 必须先破除的误解

> **纯 H5 做不到本地定时通知。**

- `setTimeout` 在后台被冻结；
- Notification Triggers API 已废弃；
- Periodic Background Sync 在 iOS 不支持。

⇒ 纯 H5 的提醒 **100% 依赖后端 cron 主动推送**；**套壳成 App 后立刻反转**（原生容器有 `AlarmManager`）。

## 3. 渠道方案（结论）

两端差异的根源 = **厂商推送服务在国内是否可达**。

| 渠道 | 结论 | 说明 |
|---|---|---|
| **iOS Web Push** | ✅ **P0 采用** | iOS 16.4+ 走 APNs，**国内可达、不需要 Apple 开发者账号**。前置：站点**添加到主屏**（判定 `navigator.standalone === true`）。⚠️ SW 的 push handler **必须无条件 `showNotification()`**（否则 Safari 撤销权限）。需 VAPID 密钥 + `push_subscriptions` 表 + `webpush-go`，出网放行 `*.push.apple.com` |
| **Android** | ✅ **P0 打包 APK（Capacitor，不上架）+ 原生本地通知** | ⚠️ 打包的意义**不是能接推送 SDK，而是有了原生容器可做本地定时通知** —— 完全不需要 FCM / 厂商通道 / 个推 / 极光。推荐 **Pull-based**：`AlarmManager`/`WorkManager` 定时唤醒 → `GET /z1/api/v1/notify/pending?since=<ts>` → 服务端算好该提醒什么 → 逐条发本地通知 → 已发 id 回传（幂等） |
| **Web Push（Android / 桌面 Chrome）** | ❌ **不可用** | 走 FCM，**被墙**；国产浏览器（UC/QQ/夸克/小米）直接不支持 ⇒ **不要给用户展示一个永远点不动的按钮** |
| **ICS 日历订阅** | ✅ **P1 顺手做** | `GET /z1/api/v1/notify/calendar.ics?token=`，含 `VALARM`（提前 1 天 09:00 + 当天 09:00）。覆盖**倒数日 / 纪念日 / 经期预测 / 还款日**。⚠️ token 必须**长期有效且不可猜**（日历客户端不刷新 token）；只能做事件型，做不了"你今天还没打卡" |
| **Webhook** | ✅ **P1** | 定位：Android 未打包时的过渡 / 打包后双保险 / **桌面端唯一可行的推送路径**。渠道：ntfy（可自建）、Bark（iOS）、飞书/钉钉/企微群机器人。⚠️ 微信服务号订阅通知**个人主体开不了** |
| 聚合推送（个推/极光/厂商通道） | **P2** | 只在"要上架"或"必须分钟级实时"时才接；自用不需要 |

### 3.1 Android 必踩三坑

1. Android 8+ 必须建 `NotificationChannel`，否则 `notify()` **静默失败**；
2. `POST_NOTIFICATIONS` 是运行时权限（Android 13+）；
3. `RECEIVE_BOOT_COMPLETED` —— 不加则**重启后闹钟全丢且无报错**。

## 4. 统一架构（待实施）

```
Notify(userID, type, title, body, refID)
   ├── 站内      ← 必写（唯一 100% 可控）
   ├── WebPush   ← 仅当有 push_subscription
   ├── Webhook   ← 按用户配置
   └── Android   ← 反向拉取（pending 接口）
```

| 规则 | 说明 |
|---|---|
| **去重键** | `type + refID + date`，**加唯一索引且必须显式命名**（否则 GORM AutoMigrate 误删 → `Error 1553`） |
| **静默时段** | **22:30 – 07:30**（否则用户直接关权限，之后再无触达渠道） |
| 调度 | GoFrame `gcron` 每分钟扫：`tasks.reminder_at` / 习惯未打卡 / 经期预测 / 预算超支 |
| 新增表 | `push_subscriptions`、`notify_channels`、`app_devices` |
