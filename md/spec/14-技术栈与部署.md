# 14 · 技术栈与部署

## 1. 技术选型

| 层 | 选型 |
|---|---|
| 后端 | Go + **GoFrame v2** + GORM（Gen 生成 DAO）+ MySQL 8 |
| 移动端 | Vue 3 + Vite + **Vant 4** + Pinia + **ECharts**（`vue-echarts`）+ `chinese-days`（农历） |
| 桌面端 | React 18 + Vite + **Semi Design** + Zustand + **Chart.js** |
| 图标 | **lucide `0.300.0`**（两端精确锁版本） |
| 部署 | 树莓派 Docker（API）+ 宿主 nginx（静态）+ Cloudflare Tunnel 对外 |

## 6. 工程纪律（⚠️ 血泪，改代码前必读）

### 6.1 数据库

| # | 纪律 |
|---|---|
| 1 | **DDL 双副本**：`db/init.sql` + `manifest/sql/0001_init.sql`；改 model 还要检查 `dao/db.go` AutoMigrate |
| 2 | **索引 tag 必须显式写名**（否则 GORM AutoMigrate 误删 → `Error 1553`） |
| 3 | **跑 SQL 用 `scripts/sqlrun/main.go`**，⚠️ **不要用 `init_db.go`**（走连接池且失败只记日志） |
| 4 | **共享库清理先 SELECT 白名单**再逐条 DELETE，**禁止拿列表查询当清理范围** |
| 5 | 迁移脚本要**幂等**（重跑影响 0 行） |
| 6 | 新 model 必加 AutoMigrate + `0001_init.sql` |

### 6.2 代码

| # | 纪律 |
|---|---|
| 7 | ⚠️ **项目无 git** ⇒ **归档先于删除** |
| 8 | **同一文件多处改动必须串行 Edit**，改完 grep 复核（并行 Edit 会互相覆盖） |
| 9 | **错误必须外显**：`response.Error(r, c, errs...)` + `details.cause`；⚠️ **禁止 store 层裸 `catch {}`** |
| 10 | **后端空切片序列化 = `null` 不是 `[]`** ⇒ 数组字段必须在 store 入口 `?? []` 归一化 |
| 11 | GoFrame 路由级中间件**必须走子分组** `group.Group("")` |
| 12 | 业务表主键是 `VARCHAR(32)`（`utility.NewID`），不是自增 |

### 6.3 前端

| # | 纪律 |
|---|---|
| 13 | ⚠️ **lucide 锁精确 `0.300.0`**，只升一端 = 图标集体失联；图标名须在两端白名单交集内 |
| 14 | ⚠️ **移动端 `van-popup` 必须 `teleport="body"`**（含嵌套），不要靠 z-index |
| 15 | ⚠️ **移动端一屏高度只认 `--app-height`**，禁 `100vh`/`100dvh`/`height:100%`；页面根不写 height |
| 16 | ⚠️ **Vue 模板注释不能写在标签属性之间**（build 直接挂） |
| 17 | ⚠️ **VantResolver 必须 `importStyle:false`**（否则按需 popup css 反杀 toast 黑底） |
| 18 | ⚠️ **分类树走 `catStore.ensureFresh()`（SWR）**，store 外禁直调 `fetchTree` |
| 19 | ⚠️ **「彩色圆底 + 图标」一律用 `IconBox`**，禁止给 `<Icon>` 加 class 设宽高 |
| 20 | 金额展示一律走 `<MoneyText>`；成功提示一律走 `utils/feedback.ts` |
| 21 | ⚠️ **三处同改**：新增记录/统计二级 tab 要同时改 `STAT_TABS`/`RECORD_TABS`、`usePageChrome`、`stores/*` |

### 6.4 校验脚本

- `scripts/sync-brand-assets.py`：品牌资源同步 + SHA256 比对（退出码 2 = 不一致）。⚠️ 只在 logo 更新时手工跑，**不进构建流程**。
- 两端常量（`banks.ts`、`account.ts`、`names.ts`、`ICON_GROUPS`、`health.ts`）用 **SHA256 校验**确保逐字一致。

## 7. 分支与发布

- `push main` 即上线；镜像在 Pi 上**原生构建**（arm64）。
- 发布前：两端 `npm run type-check` / `build` 必须绿；后端 `go build` + `go vet` + `go test` 三绿。
- ⚠️ 产物核对要认准**部署目录**：仓库根 `dist/z1` + `dist/z1-app` 才是部署产物；两个子项目里各自的 `dist/` 是**历史遗留**，看错会得出相反结论。
