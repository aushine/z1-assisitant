# Z1 · 总集 Spec（当前唯一有效规范）

> **产品**：life-assisitant（代号 **z1**）—— 个人生活助手，覆盖 **任务 · 习惯 · 记账 · 健康 · 统计** 五件事。
> **形态**：**双端 Web**（移动端 H5 + 桌面端 Web），共用**同一套后端与同一个数据库**。
> **本文的定位**：这是**总集活文档**，描述的是「**现在代码里是什么样**」——不是某一次的设计稿。
> **基准时间**：2026-09-24 代码实测
>
> ⚠️ **与历史文档的关系**：2026-08 至 09 的 14 批设计文档已归档到 `md/archive/`（**仅本地保留，未纳入版本库**），**只读不改**。
> 两者冲突时，**以本文为准**；本文与代码冲突时，**以代码为准并回来改本文**。

## 6. 编写与维护约定

1. **写实不写愿**：本文只描述已落地的东西。设计中未实现的，明确标 `⬜ 未实施` 并写清依据。
2. **带证据**：关键结论（尤其"已实现/未实现"）附 `文件:行号` 或文件路径。
3. **双端差异必须显式写出**，不允许只描述一端。
4. **新增/修改后同步更新本文 §5 状态一览与 [99-附录 §4 断线清单](./99-附录.md)**。
5. 每个模块篇统一结构：**是什么 → 信息架构 → 关键规则 → 接口 → 端差异 → 已知问题**。
