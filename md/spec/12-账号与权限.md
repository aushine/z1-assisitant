# 12 · 账号与权限

## 1. 认证

### 1.1 JWT

| 项 | 值 |
|---|---|
| Claims | `user_id` / `role` / `device_id` / `token_type` |
| 算法 | HS256；**access 与 refresh 用两把不同密钥** |
| access TTL | **4 小时** |
| refresh TTL | **7 天** |
| issuer | `life-assistant` |
| 密码哈希 | bcrypt，cost 12 |

### 1.2 Refresh Token（rotation）

- 表 `refresh_tokens`：只存 **SHA-256 哈希**（`token_hash` unique），带 `device_id`、`device_info`、`ip`、`expires_at`、`revoked_at`。
- 刷新流程：解析 → 校验 `token_type=refresh` → 校验 `device_id` 一致 → 查 hash 且未撤销未过期 → **撤销旧 refresh** → 签发新一对。
- 登出：`all_devices=true` 撤销全部；否则只撤销当前。
- 改密 / 重置密码都会 `RevokeByUser` 强制全部下线。
- 会话管理：`GET /auth/sessions`、`DELETE /auth/sessions/:id`。

### 1.3 存储与前端

| 端 | 存储 | 静默刷新 |
|---|---|---|
| 移动端 | localStorage（`access_token` / `refresh_token`） | ✅ **已实现**：`isRefreshing` + `pendingRequests` 并发队列，15s 超时兜底，失败跳登录 |
| 桌面端 | localStorage | ⚠️ **只有脚手架**（`_isRefreshing` / `refreshSubscribers` 空壳），**未接线** |

### 1.4 其他规则

| 项 | 规则 |
|---|---|
| 密码长度 | 登录 6–32；注册/改密/重置 8–32 |
| ⚠️ 密码强度 | **后端无强度校验**（只有长度）；"字母+数字"只存在于前端且**登录页仅警告不阻断** |
| 登录失败 | **5 次锁 10 分钟**（⚠️ 写死在代码，配置 `loginMaxFailures` 未被读取） |
| 注册 | ⚠️ **不接受自选角色**，恒落 `user`（防提权） |
| 忘记密码 | ⚠️ **重置 token 只打到日志**（进程内缓存 5 分钟），**不真发邮件**；邮箱不存在静默成功 |
| 其他登录方式 | 全部是 toast「即将上线 / 开发中」的占位 |

## 2. RBAC

### 2.1 表结构

| 表 | 关键 |
|---|---|
| `roles` | `code` 是主键（`varchar(20)`）、`is_system`、`user_count` |
| `permissions` | `module`、`action`（id = `p_<module>_<action>`） |
| `role_permissions` | 复合主键 `(role_code, permission_id)` + `enabled` + `version` |

### 2.2 权限点

- 命名：**`module:action`**（如 `finance:view`）。
- **48 条 / 15 模块**：`home`、`task`、`habit`、`category`、`mood`、`finance`、`period`、`health`、`anniversary`、`stat`、`timeline`、`notification`、`me`、`user_mgmt`、`role_mgmt`。
- 矩阵：**admin = 48 全量**（矩阵锁定、不可删）；**user = 38**（排除 `user_mgmt` / `role_mgmt` 两个模块）。
- ⚠️ `editor` / `viewer` **已废弃删除**（存量用户改挂 `user`）。自定义角色运行时创建（`role_mgmt:create`）。

> ⚠️ **权限点目录的唯一真源是 `db/init_data.sql`**，不在 Go 代码里。router.go 以字符串字面量引用 —— **改目录必须同步 router.go**。

### 2.3 中间件

```go
group.Group("", func(g *ghttp.RouterGroup) {
    g.Middleware(middleware.RequirePermission("user_mgmt:view"))
    g.GET("/users", User.List)
})
```

- `RequirePermission(points...)` 是 **ANY-of**；**admin 代码旁路直通**。
- 多 action 共享路由时传多个点做粗筛，controller 内再用 `PermissionGranted(ctx, role, point)` 细分。
- ⚠️ **GoFrame v2 坑**：路由级中间件**不能当第三参传**（`group.GET(pattern, obj, params...)` 的第三参不是中间件链），必须用 `group.Group("")` 派生后 `.Middleware()`。
- 会话生命周期路由（me/logout/refresh/sessions/permissions 目录）**不挂权限点**。

## 4. 乐观锁（`version`）

| 场景 | 规则 |
|---|---|
| `PATCH /users/:id/status` | **必带** `version` |
| `PATCH /users/:id` | 用 `req.Version + 1` |
| `PATCH /users/me` | **可选**：显式带则校验，不带则用服务端当前值 |
| `POST /auth/change-password` | 服务端自增 |
| `PUT /users/:id/role` | 服务端自增 |

冲突 → **`409001 VersionConflict`**。⚠️ 更新用户/账户时**必须带 `version`**。
角色矩阵也有 `version`，`GET /roles/:code/permissions` 会回传。
