## 2. 全局约定

| 约定 | 说明 |
|---|---|
| 主键 | 业务表一律 **`VARCHAR(32)`**，由 `utility.NewID("xx")` 生成（**不是** 自增 bigint） |
| 软删除 | `deleted_at`；恢复窗口 30 天 |
| 时间 | `created_at` / `updated_at`；业务日期字段 `date` 是**用户本地日期，后端不做时区换算** |
| 金额 | 一律 `DECIMAL`，**`transactions.amount` 恒为正，方向由 `type` 表达** |
| 所有权 | 所有业务表带 `user_id`，查询必须带 `user_id` 条件 |
| JSON 字段 | 简单标签用 JSON 列，不建关联表（如 `period_days.symptoms`、`health_settings.metrics_enabled`） |

## 3. 账户（`accounts`）—— 三层体系

```
L1 大类（不落库，由 L2 派生）      L2 类型（18 个，落库 type）        L3 机构（322 家银行）
  资金 asset      ←────────────── cash 现金 / saving 储蓄卡 / alipay 支付宝
                                  yuebao 余额宝 / wechat 微信钱包 / prepaid 储值卡 ...
  信用 credit     ←────────────── credit 信用卡 / huabei 花呗 / baitiao 白条
                                  loan 贷款 / other_credit ...
  理财 investment ←────────────── fund 基金 / stock 股票 / bank_fin 银行理财
                                  gold 黄金 / other_invest ...
```

| 规则 | 说明 |
|---|---|
| **L1 不存列** | 由 L2 注册表派生（`internal/utility/account_vocab.go`），避免 "type 与 category 打架" |
| **L2 保留 4 个旧值** | `saving` / `credit` / `huabei` / `wechat` 一字不改（存量兼容） |
| **`institution`** | `varchar(20)`，存银行 code；**不加索引**；后端只校验长度，不校验白名单 |
| **`icon`** | ⚠️ 已扩到 **`varchar(32)`**（`lucide:CandlestickChart` = 22 字符，超 20 会静默截断） |
| **⚠️ 信用类余额存负数** | 不再是"存正数、计算时减"。**净资产 = `SUM(全部 balance)`** |
| 余额不足拦截 | 只作用于 asset / investment（信用类天然为负，不能拦）；**「直接改余额」永不拦** |
| 跨 L1 改类型 | 前端负责：跨 `asset ↔ credit` 提示 + **余额自动取负**；同 L1 不动 |

**银行清单**：不建表，两端 + 后端各一份常量（`banks.ts`，**322 家**，其中 **153 家有 logo**），逐字一致 + SHA256 校验。缺 logo 的 169 家走**文字徽标兜底**（品牌色圆角块 + 简称首字）。

**符号归一迁移**（已执行）：`UPDATE accounts SET balance = -balance WHERE type IN (信用类) AND balance > 0 AND deleted_at IS NULL`。⚠️ **两个条件缺一不可**：type 限定防误伤资金类，`balance > 0` 保幂等。

## 4. 交易（`transactions`）

| 列 | 说明 |
|---|---|
| `type` | `expense` / `income` / **`transfer`** |
| `amount` | **恒为正**，方向由 type 表达 |
| `category_id` + `category_name` | id 是权威，**name 是历史快照**（改名也不丢） |
| `category_emoji` | ⚠️ **已停止写新值**（仅存量兼容） |
| `account_id` | 转账另有 `to_account_id` |
| `exclude_budget` | 不计入预算（如"给他人送人情"） |
| `exclude_stats` | 不计入收支 |
| `source` | `''` 普通 / `balance_adjust` 余额调整 / `reimburse` / `lend` / `borrow` / `refund` |
| `contact` | 对方（`varchar(50)`） |
| `settle_of` | 关联原笔 id（核销），不加索引 |
| `happened_at` | `TIMESTAMP`，**已含时间**（记一笔可选到分钟，无需改表） |

### 4.1 三个"性质"功能共用一个机制

**待报销 / 借入借出 / 退款关联**不建新表：

- 状态**派生不落库**："已报销/已收回/已退款" = 是否存在指向本笔的核销记录（`settle_of`），支持**部分核销**。⚠️ 落 `state` 字段必然"状态与流水对不上"。
- **资金流走真实流水**：每个动作都生成普通交易 ⇒ 账户余额自动正确，无需影子余额。
- 入口分两侧：**记一笔**里选「性质」；**核销类动作**（报销到账/收回/还回/退款）**从原笔详情页发起**。

### 4.2 两个口径开关完全独立

`exclude_budget` 与 `exclude_stats` **不做任何联动**（允许"不计收支但计入预算"）。
可见性：不计预算只在**支出**；不计收支在**支出/收入**；**转账都不给**。

## 5. 分类体系

### 5.1 财务分类 `finance_categories`（两级）

- **复合主键 `(id, user_id)`**（只写 `PRIMARY KEY(id)` 会让第二个用户播种全部撞主键被 `INSERT IGNORE` 静默丢弃）。
- `parent_id` **空串 = 一级**（⚠️ **不能用 NULL** —— MySQL 唯一索引里 NULL 不参与比较，同一用户可有多个"餐饮"，约束静默失效）。
- 软删三件套一起写：`is_deleted=1`、`deleted_at=NOW()`、**`deleted_seq = 自身 id`**（唯一索引末列用它，否则"同名→删→重建→再删"会撞 1062）。
- **索引 tag 必须显式写名**：`uk_fin_cat_user_scope_parent_name` 等（否则 GORM AutoMigrate 会误删索引 → `Error 1553`）。
- **种子**：20 个一级（12 支出 + 8 收入）+ **85 个二级 = 105 条**，写在 `utility/finance_category_seed.go`（**不进 SQL**，每用户一份）。**85 个二级全部有独立 icon**，有单测断言防回归。
- **懒创建触发条件**：存在任何 `is_builtin=1` 的行（**含已删除**）—— 不能用"当前分类数是否为 0"，否则用户删光后重进会被重新塞满。
- **聚合必须按 id**：`GROUP BY COALESCE(category_id, CONCAT('n:', COALESCE(category_name,'未分类')))`（用 `CONCAT('n:',name)` 兜底，让未映射老数据仍按名字各自成组，不挤成一条"未分类"）。
- ⚠️ **`SumExpenseByCategory` 必须含子分类归集**（`category_id = ? OR category_id IN (SELECT ... WHERE parent_id = ?)`），否则用户给"餐饮"设预算却记"餐饮-三餐"，已用额度永远显示 0。

### 5.2 习惯/待办分类 `user_categories`

- 与 `finance_categories` **分开的表**（不合并，避免动已上线的复合主键核心表）。
- **只做一级**（D21：数量少、选择频率低，两级会让"一屏选完"变成"点两次"；表结构预留 `parent_id`）。
- ⚠️ **分类 id 保留旧值**：习惯继续存 `sport/diet/life/study`、任务继续存 `c_work`…，它们直接成为内置分类的 id ⇒ **存量零迁移、统计 SQL 一行不用改**。
- 懒创建播种（`utility/user_category_seed.go`）；建习惯时也补种。

## 6. 健康（3 张表）

```
health_events（真源，一天多次，不延续）
        │ 同事务 recomputeDaySummary
        ▼
health_days（日汇总缓存）
```

| 表 | 定位 | 关键列 |
|---|---|---|
| `health_events` | **唯一真源** | `date`、`time_of_day "HH:mm"`、`metric_key`、`value_num` / `value_int`、`note` |
| `health_days` | 日汇总缓存 | `water_ml`（累计）、`weight_kg`、`bbt`、`sleep_hours`、`bowel_count`、`bowel_type` |
| `health_settings` | 用户级配置 | `metrics_enabled` json、`water_goal_ml`（默认 1500）、`water_step_ml`（默认 200）、`setup_done_at` |

- `metric_key`：`water` / `bbt` / `weight` / `sleep` / `bowel`（只有 bowel 用 `value_int`）。
- ⚠️ **`weight` 日汇总取最早一次**（晨起口径，与 `bbt` 一致），有重算脚本 `scripts/weightrecompute`。
- `health_settings` **懒创建**，`GET /health/settings` 永不 404。
- ⚠️ `metrics_enabled` 要区分 `nil`（从未配置，给默认值）与 `[]`（主动全关）。

### 6.1 心情 `mood_logs`（⚠️ 按小时）

- **`UNIQUE(user_id, date, hour)`**，`hour` 0–23。
- `mood` 1–5（0 = 该小时确无心情，**读取时向前延续**）；`energy` 1–3，NULL ≡ 不填；`note` 不延续。
- ⚠️ **`hour` 不带 gorm `default` tag**（否则 hour=0 午夜会被当零值静默写成 12）。
- 特殊槽位：**`hour = 12` 是经期日记槽**（一天一条，与小时制共用同一张表）。
- `PUT /moods` 按 `(user_id, date, hour)` **upsert**；不传 `hour` 时取服务器当前小时。

## 8. 迁移纪律（⚠️ 血泪）

| # | 纪律 | 原因 |
|---|---|---|
| 1 | **DDL 双副本同步** | `db/init.sql` + `manifest/sql/0001_init.sql`；改 model 还要检查 `dao/db.go` AutoMigrate |
| 2 | **索引 tag 必须显式写名** | 否则 GORM AutoMigrate 误删索引 → `Error 1553` |
| 3 | **跑 SQL 用 `scripts/sqlrun/main.go`** | ⚠️ **不要用 `init_db.go`**（走连接池且**失败只记日志**，你会以为跑成功了） |
| 4 | **共享库清理先 SELECT 白名单** | ⚠️ 再逐条 DELETE，**禁止拿列表查询当清理范围**（删错就是别人的数据） |
| 5 | **迁移脚本要幂等** | 可重跑；重跑影响行数应为 0 |
| 6 | **归档先于删除** | ⚠️ 项目**无 git**，删了就没了 |
| 7 | 新 model | 必加 AutoMigrate + `0001_init.sql` |
