# 00 · 总览

## 1. 产品是什么

**Z1（life-assisitant）** 是一个**个人自用**的生活助手：把"任务、习惯、钱、身体"四件每天都会发生的事记下来，并在需要时把它们重新组织给你看。

一句话定位：

> **记得住**（每天 10 秒记完）· **看得见**（首页就能知道今天要做什么）· **有人提醒**（⚠️ 这一条目前还是断线，见 §6）

### 1.1 产品边界

| 是 | 不是 |
|---|---|
| 个人单用户（有角色体系但为自用预留） | 多人协作 / 分账 / 社交 |
| 轻量记账（流水 + 预算 + 账户 + 债权债务） | 复式记账 / 科目体系 / 多币种 |
| 生活记录与健康观察 | 医疗诊断 / 设备同步 / 孕期管理 |
| 双端 Web，同一后端 | 原生 App（Android 打包仅作为通知手段讨论，未实施） |

## 2. 五个模块与它们的职责

| 模块 | 一句话职责 | 用户什么时候用 |
|---|---|---|
| **首页** | 今天不用点进去就该知道的 | 每天多次，打开就看 |
| **任务** | 待办清单（有截止、优先级、子任务、循环） | 想起有事没做时 |
| **记录** | 往里灌数据的地方（习惯打卡 / 记一笔 / 记身体指标） | 事情发生的当时 |
| **统计** | 把已有数据重新组织给你看 | 一周/一月回顾时 |
| **我的** | 长期设定与档案（资料、偏好、纪念日、分类、安全） | 偶尔设置 |

**落位口诀**（新功能该放哪，详见 [01 §2](./01-信息架构与导航.md)）：

> **流水 → 记录**（每天往里灌数据）
> **档案 → 我的**（长期设定与资产）
> **镜子 → 统计**（把已有数据重新组织）
> **今天 → 首页**（不用点进去就该知道）

## 3. 双端策略

两端**共享信息架构、数据契约与后端**，**各自使用本端的交互习语**（这是有意为之，D14）。

| 维度 | 移动端（`life-assisitant-ui-mobile`） | 桌面端（`life-assisitant-ui-desktop`） |
|---|---|---|
| 技术栈 | Vue 3 + Vite + Vant 4 + Pinia | React 18 + Vite + Semi Design + Zustand |
| 基准尺寸 | **375 × 812** | 侧栏 260px + 内容区（`max-width:1280px` 居中） |
| 访问路径 | `/z1-app/` | `/z1/` |
| 一级导航 | 底部胶囊 Tab Bar（5 项） | 左侧栏（个人功能 5 + 系统管理 2） |
| 二级切换 | `SubTabBar` 分段控件（**上限 6 个**） | Semi `Tabs` / `Select` |
| 表单承载 | 底部半屏 `van-popup` / 二级路由页 | `SideSheet` 抽屉 / `Modal` |
| 列表分页 | `van-list` 上拉加载 | `Table` + `Pagination` |
| 批量操作 | 长按进入多选模式 + 底部操作栏 | 表头 Checkbox |
| 左滑/右键 | `van-swipe-cell` 左滑 | hover 显示 / 右键 Dropdown |
| 图表 | **ECharts**（`vue-echarts` + `useChartTheme()`） | **Chart.js**（`react-chartjs-2`） |
| 图标 | `lucide-vue-next` | `lucide-react` |
| Token 静默刷新 | ✅ 已实现（并发队列） | ⚠️ 只有脚手架，未接线 |

> ⚠️ **两端必须逐字一致的**：图标名注册表 `ICONS`、`ICON_GROUPS`、银行清单 `banks.ts`、账户类型 `account.ts`、健康指标表 `health.ts`、分类种子 `finance_category_seed.go`、品牌资源 `public/brand/*`。
> 有 SHA256 校验脚本兜底。

## 6. 现在最该补的三根线

> 骨架已经扎实（24 张表、5 个模块、48 个权限点），**缺的是把已建好的东西接上**。

| # | 断线 | 现状 | 为什么重要 |
|---|---|---|---|
| **1** | **通知投递引擎** | `notifications` 表 + 5 类型枚举 + DTO + 列表页齐备，**但全库无任何一处创建通知、无 cron** | 习惯类产品没有触达 = 三天流失 |
| **2** | **循环任务实例化** | `recurrence_rule` 支持 DAILY/WEEKLY/MONTHLY，**只存不生成** | "设了每天"却只出现一次，等于没做 |
| **3** | **`/sync` 是假接口** | 直接返回"同步完成"，用户会误以为有备份 | 这不是功能，是误导 |

另外：**时间线只能看今天**（后端支持 `?date=`，前端写死）、**无全量导出/导入**、**无目标层与周报月报**。

完整清单与优先级见 [99-附录 §4](./99-附录.md)，通知方案见 [13-通知与触达](./13-通知与触达.md)。

## 7. 明确的 Non-goals（全产品级）

| 不做 | 理由 |
|---|---|
| 多人协作 / 分账 / AA / 社交排行榜 | 需要成员体系与账本，是另一个产品形态 |
| 复式记账 / 借贷分录 / 科目体系 | 个人记账用不上，会把产品做重 |
| 多币种 / 汇率 | 与定位无关 |
| 信用卡账单日 / 额度 / 免息期管理 | 会做成"信用卡管家" |
| 完整 OKR / 项目管理 | 轻量 Goal 足够 |
| 无边界 AI 聊天助手 | 真要做应从"可解释的回顾"里长出来，而不是接聊天框 |
| 医疗级诊断 / 设备同步 / 孕期模式 | 合规与责任边界 |
| 扩容一级导航 / 可配置导航 | 5 个一级是稳定的心智模型 |
