## 0. 背景（为什么做这一批）

2026-10-01 18:48–18:58 罗格提交了一批目录改名，把已上线批次标记为"完成"。但**命名不符规范**，直接导致主理人状态机 `z1-fsm.py` 误判：

**问题现状**

| 目录名（现状） | 后缀写法 | 状态 |
|---|---|---|
| `md/spec-20260924-v1√` | **裸 `√`** | ❌ 不符规范 |
| `md/spec-20260924-v2√` | **裸 `√`** | ❌ 不符规范 |
| `md/spec-20260924-v3√` | **裸 `√`** | ❌ 不符规范 |
| `md/spectest-20261001-v1√` | **裸 `√`** + 目录名不合 `spec-yyyyMMdd-vX` | ❌ 不符规范 |

**PROCESS.md §3.3 规定**：完成信号为目录名后缀**全角 `(√)`**（全角左括号 + 全角根号 + 全角右括号），即 `md/spec-20261001-v1(√)`。

**造成的后果**

1. `z1-fsm.py` 的 `find_active_spec()` 正则 `^spec-(\d{8})-v(\d+)(\(\u221a\))?$` **只认全角 `(√)`**；裸 `√` 不匹配 → 全部落入 fallback 分支。
2. fallback 分支用 `os.listdir` **不做排序** → 误选中 9/24 的 `spec-20260924-v1√` 当作"当前活跃批次"，并因"带 √"判定"已完成 → 核验通过"。
3. 测试批次 `spectest-20261001-v1√` 目录名不合 `spec-yyyyMMdd-vX` 规则 → **被状态机完全忽略**。

> 结果：一旦 hook/cron 轮询触发，会把 9/24 的老批次当成新批次**重复部署**并误发上线通知。**这是主理人状态机的误判源头，必须在本批收口。**
